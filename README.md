# 今日の学習（v0.5.0）
計画 → 学習（一時停止あり）→ 振り返り → 記録。サーバー・ログイン・外部通信なし。記録はlocalStorage（キー `gakushu-shien:v1`）。

## ローカルで確認
このフォルダで `python3 -m http.server 8000` を実行し、ブラウザで http://localhost:8000/ を開く。

## 公開
GitHubにpush → Settings → Pages → Deploy from a branch → main → /(root) → Save。
`https://ユーザー名.github.io/リポジトリ名/` で開く（CSS・JSは相対パス）。

## ファイル
index.html / style.css / app.js / README.md

## 記録の項目
id, v(形式), appVersion, subject, task, firstStep, endCondition, startMode(planned|now), plannedStart, startedAt, endedAt, pauses[{from,to}], status, achievement, focus(1-5/null), trouble, nextTry。日時はISO形式(UTC)で保存し、画面では端末の時刻で表示。

## v0.4.0 追加：集中・使いやすさ
- 前提の明記：計画画面の「このアプリの考え方」。調査の関連（計画×集中 ρ=.382、開始時刻の固定×平日学習 ρ=.414、就寝時刻の固定×計画 ρ=.329）を示し、原因は未確認と書く。睡眠の「長さ」と集中の順位相関はほぼ0だったため、睡眠は長さでなく時刻の固定として扱う。
- スマホ対策：学習中はメニューを隠す集中モード／画面を点けたままにする（Wake Lock、未対応の端末では無効）／始める前の準備チェック／2秒以上画面を離れた回数（leaves, leaveMs）を記録。責める文言は使わない。
- 必須（青い枠＋「必須」）と任意（グレー＋「任意」）を色と文字で区別。CSSの `:has()` を使う。
- ポモドーロ：ドーナツ型の進み具合、中央にデジタル表示、開始・終了で音（Web Audio）と振動、音のオン／オフ。ヘッダーに現在時刻。音は一度画面をさわった後に鳴る。ブラウザを閉じていると鳴らない。
- 続けたくなる工夫：短時間の出発点テンプレ（5分・思い出す ほか。効果の保証はしない）、直近7日の積み上げ（0日を罰しない）、「いつもの時刻」ボタン（予定2回以上で表示）、保存時のねぎらい、昨夜の睡眠（任意）。
- 追加した記録項目：prep[], sleepHours, leaves, leaveMs。CSV追加列：sleep_hours_prev_night, screen_leave_count, screen_leave_seconds, prep_checked。古い記録も読める。
- 確認（未実施）：開始・区切り・休憩終了の音が1回ずつ鳴る／ドーナツの進みと中央の時間／再読み込み後の表示／別タブ移動で回数が増え、1秒未満では増えない／必須・任意の見分け／スマホ幅で崩れない／ダークモード。

## v0.5.0 追加：タスク・優先度・振り返り・仲間の状況
- タスク画面：今日のタスクを書き出し、優先度（高・中・低）を自分で決める。あとで「優先度を変える」で循環。高い順に並ぶ。起動時に今日のタスクが空ならこの画面から始まる。昨日の未完了の持ち越し、タスクから学習の計画を始める機能。
- 学習中の画面：残りのタスクをチェックで消していき、進み具合（完了/全体）を表示。
- 今日の振り返り：「今日できたこと」「明日に生かすこと」（どちらか1つで保存可）。記録画面の期間内に一覧表示。
- 仲間の状況カード：**サーバーがないため、リアルタイムの共有はできない。** 本人が書き出したカード（JSON）を相手が読み込んで見る。カードの中身は表示名・直近7日の日ごとの学習分・今日のタスク完了数のみ。課題名・自由記述・記録は含めない。読み込み時に形式を検査し、必要な項目だけ作り直して別キー（`gakushu-shien:peers`）に保存。順位づけ・比較ランキングはしない。20人分まで。
- データ：`days` を追加（タスク・振り返り）。JSONの書き出し・読み込みに含め、同じIDは追加しない。全件削除で仲間のカードも消える。CSVにはタスクを含めない。
- 確認（未実施）：タスク追加→優先度の変更と並び順／学習中のチェックで進み具合が変わる／再読み込み後の復元／日付をまたいだ持ち越し／カード書き出し→別ブラウザで読み込み／壊れたカード・同じ人のカード／JSON読み込みでタスクが統合される。
- 検討事項：本当のリアルタイム共有には、サーバーと本人確認・個人情報の設計が必要になり、最初の方針と変わる。
